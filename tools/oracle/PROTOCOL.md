# Oracle protocol v1

The oracle is a JSON-lines (JSONL) service: one request object per line on
stdin, one response object per line on stdout. It links the pinned upstream
`libupb` (commit `2de70d710510ea7c5ad7ec0c72bfed7f411c7b60`) and exposes the
**observable behavior** of upb's primitive wire-reading surface.

The oracle and the DUT (upb-rs) are separate processes; they never share
memory (§19). Requests are generated by the court corpus generators, and the
DUT runs the identical logical operation through the Rust implementation.

## Versioning

Every request and response carries `"v":1`. A response is always emitted for
every request (even malformed ones), so courts can pair them by `id`.

## Transport

- stdin/stdout, one JSON object per line, no pretty-printing.
- `id` is an opaque non-negative integer echoed from request to response.

## Request shape

```json
{"v":1,"id":1,"op":"read_varint","hex":"ff8001"}
{"v":1,"id":2,"op":"read_tag","hex":"08"}
{"v":1,"id":3,"op":"read_size","hex":"0a"}
{"v":1,"id":4,"op":"read_fixed32","hex":"78563412"}
{"v":1,"id":5,"op":"read_fixed64","hex":"0807060504030201"}
{"v":1,"id":6,"op":"skip_varint","hex":"ff80"}
{"v":1,"id":7,"op":"skip_value","tag":10,"hex":"03aabbcc"}
{"v":1,"id":8,"op":"skip_group","tag":11,"hex":"12 34 0c"}   // group body, tag = start-group tag value
{"v":1,"id":9,"op":"ping"}
```

`hex` is the payload (after any tag), lowercase hex, no spaces. `tag` is the
already-parsed tag value (`field_number << 3 | wire_type`), decimal.

## Response shape

```json
{"v":1,"id":1,"status":"ok","value":"127","consumed":2,"bounded":true}
{"v":1,"id":1,"status":"eof"}
{"v":1,"id":1,"status":"error","code":"malformed","consumed":0}
```

- `status:"ok"` — the primitive read succeeded through the upstream reader
  API. `value` is always a decimal **string** (u64 precision), `consumed` is
  the byte count past the start of the payload, and `bounded` says whether the
  consumed position is within the valid read region of the eps-copy stream
  (i.e. the decoder's next `IsDone()` would not report an error).
- `status:"eof"` — the input was empty; the decoder loop would not perform a
  read at all.
- `status:"error","code":"malformed"` — the upstream reader returned NULL
  (e.g. 10 continuation bytes in a varint, 5-byte tag exceeding UINT32_MAX,
  5-byte size exceeding INT32_MAX, wire type 6/7, field number 0, group depth
  exceeded, delimited size extending past the stream limit).

## Semantics reference (upstream sources)

- `upb/wire/internal/reader.h` — fast paths for one-byte varints/tags/sizes.
- `upb/wire/reader.c:19-61` — long varint/tag/size loops; note the
  `val += (byte - 1) << (i * 7)` arithmetic and the `UINT32_MAX`/`INT32_MAX`
  rejections.
- `upb/wire/eps_copy_input_stream.h` + `internal/eps_copy_input_stream.h` —
  the 16-byte slop guarantee and the zero-padded 32-byte patch buffer that
  makes raw reads past the end of short inputs succeed (with zero bytes) and
  then fail at the next `IsDone()`.
- `upb/wire/eps_copy_input_stream.c:25-47` — `IsDoneFallback`: overrun less
  than the limit copies the tail into the patch buffer; overrun past the limit
  is an error.

## Operations

| op            | reads                    | value | notes |
|---------------|--------------------------|-------|-------|
| `read_varint` | `upb_WireReader_ReadVarint`   | u64 | up to 10 bytes; (byte-1)<<7i arithmetic |
| `read_tag`    | `upb_WireReader_ReadTag`      | u32 | up to 5 bytes; >UINT32_MAX rejected |
| `read_size`   | `upb_WireReader_ReadSize`     | i32 | up to 5 bytes; >INT32_MAX rejected |
| `read_fixed32`| `upb_WireReader_ReadFixed32`  | u32 | little-endian wire bytes |
| `read_fixed64`| `upb_WireReader_ReadFixed64`  | u64 | little-endian wire bytes |
| `skip_varint` | `upb_WireReader_SkipVarint`   | —   | scans up to 10 bytes |
| `skip_value`  | `upb_WireReader_SkipValue`    | —   | wire type from tag; depth limit 100 |
| `skip_group`  | `upb_WireReader_SkipGroup`    | —   | recursive; depth limit 100 |
| `ping`        | —                        | —   | protocol self-test |

## Extensions

New ops are additive and versioned by `"v"`. Ops that read a *message* through
`upb_Decode` (with a mini table selected by descriptor) will be added as
`decode_message` etc. in a later protocol version; they require the corpus
generator to supply the mini table in the request.
